Hãy xây dựng cho tôi một ứng dụng Web Full-stack hoàn chỉnh có tên **Library Management Pro** — hệ thống quản lý thư viện hiện đại sử dụng **Supabase PostgreSQL** làm database.

## MỤC TIÊU

Đây phải là một ứng dụng thực sự chạy được, không phải mockup.

Yêu cầu bắt buộc:

* Frontend giao tiếp với Backend thông qua REST API.
* Backend sử dụng Supabase PostgreSQL làm database thật.
* Không sử dụng MongoDB, MongoDB Atlas hoặc Mongoose.
* Không dùng localStorage để thay thế database.
* Có đầy đủ CRUD.
* Có authentication cho thủ thư/admin.
* Có validation ở frontend và backend.
* Có xử lý lỗi rõ ràng.
* Responsive desktop/tablet/mobile.
* UI hiện đại theo phong cách SaaS Dashboard.
* Không dùng dữ liệu giả thay cho API.
* Không để TODO hoặc chức năng chưa hoàn thành.
* Tự cài package còn thiếu.
* Tự chạy kiểm tra bằng terminal.
* Tự sửa lỗi nếu phát hiện.
* Chỉ kết thúc sau khi kiểm tra ứng dụng thực tế.

# 4. BOOKS TABLE

Tạo bảng `books`:

```text

title
isbn
author
category
publisher
publish_year
quantity
available_quantity
shelf
description
cover_url
created_at
updated_at
```

Yêu cầu:

* `id` UUID hoặc BIGINT.
* `title` NOT NULL.
* `isbn` UNIQUE.
* `quantity >= 0`.
* `available_quantity >= 0`.
* `available_quantity <= quantity`.
* `publish_year` hợp lệ.
* `created_at` tự động.
* `updated_at` tự động.

Tạo index cho:

* title
* isbn
* author
* category

# 9. AUTHENTICATION

API:

```text
POST /api/auth/login
POST /api/auth/logout
GET  /api/auth/me
```

Login:

```json
{
  "username": "...",
  "password": "..."
}
```

Response:

```json
{
  "success": true,
  "token": "...",
  "user": {
    "id": "...",
    "username": "...",
    "role": "ADMIN"
  }
}
```

Các API quản trị phải yêu cầu authentication.

Middleware phải:

1. đọc Authorization header.
2. kiểm tra Bearer token.
3. xác minh token.
4. lấy user.
5. cho phép request tiếp tục.

Token không hợp lệ:

```http
401 Unauthorized
```

Không được bypass authentication.

# 12. BORROW BOOK

API:

```text
GET /api/borrowings
POST /api/borrowings
PUT /api/borrowings/:id/return
```

Khi mượn sách:

1. Kiểm tra reader tồn tại.
2. Kiểm tra book tồn tại.
3. Kiểm tra `available_quantity > 0`.
4. Kiểm tra due date hợp lệ.
5. Tạo borrowing.
6. Giảm available_quantity.
7. Tạo activity log.
8. Trả kết quả cho frontend.

Không được cho mượn nếu:

```text
available_quantity <= 0
```

---

# 13. TRANSACTION / DATA CONSISTENCY

Đây là phần quan trọng.

Không được để tình trạng:

```text
borrowing tạo thành công
nhưng available_quantity không giảm
```

hoặc:

```text
return thành công
nhưng available_quantity không tăng
```

Sử dụng transaction hoặc PostgreSQL RPC/function phù hợp với Supabase để đảm bảo thao tác mượn/trả là atomic.

Nếu transaction thất bại:

* rollback.
* không tạo borrowing giả.
* không thay đổi quantity sai.

---

# 14. RETURN BOOK

Khi trả sách:

```text
PUT /api/borrowings/:id/return
```

Backend phải:

1. Kiểm tra borrowing tồn tại.
2. Kiểm tra status hiện tại.
3. Nếu đã RETURNED → từ chối.
4. Ghi return_date.
5. Chuyển status thành RETURNED.
6. Tăng available_quantity.
7. Tạo activity log.

Không được tăng quantity hai lần.

# 15. OVERDUE

Không cần cron job.

Khi query:

Nếu:

```text
current date > due_date
AND status = BORROWING
```

```text
OVERDUE
```

* Tổng sách quá hạn.
* Tổng sách đang mượn.
* Danh sách reader quá hạn.
* Số ngày quá hạn.

Có thể xử lý bằng SQL query hoặc PostgreSQL view/function.

Không cần chạy cron.
